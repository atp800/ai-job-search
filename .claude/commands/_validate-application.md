# Independent final validation

Run this gate for every employer-facing application document created or revised, including a standalone CV, letter, supporting statement or portal response. It follows all drafting, editorial review, layout fixes and the ordinary verification checklist. A pass applies only to the exact inspected versions.

1. **Identify the application.** Use one stable key for the entire posting, across documents, retries and later sessions. Prefer lowercase employer plus employer requisition ID, then the canonical posting URL, then the existing application archive ID. For pasted postings without identifiers, use lowercase employer, role and location plus a stable distinguishing detail if needed. Reuse the original key on resumption. Run `python tools/application_validation.py status "<application-key>"` from the repository root. Save the returned revision. A cancelled application stays flagged; stop work on it. For an interrupted `amend`, resume the outstanding correction from the saved findings and inspect the corrected packet. Do not spend another round recording the same verdict.

2. **Prepare the inputs.** Supply the full Super CV (the original combined Word CV at the `Source:` path in `.claude/skills/job-application-assistant/01-candidate-profile.md`) and the full `documents/cover_letters/super-cover-letter.md`. Read the original Word file, extracting body, tables and nonempty headers/footers when a text rendition is needed. Preserve dates, names and paragraph boundaries. Also supply the original target posting, relevant form prompts or employer limits, and every current employer-facing deliverable in the packet. Inspect the actual output on disk, including rendered PDFs when produced. For a later addition, include the earlier documents for that application to catch contradictions. Keep submitted originals read-only. Work from the candidate's named masters even if a draft, profile summary or example template says something different.

3. **Dispatch a new independent validator** using `.claude/agents/application-validator.md`. In Claude Code use the named agent. In Codex use a fresh subagent with `fork_turns="none"` and explicitly pass the validator instructions and inputs. Each pass gets the complete current packet, both masters and posting. Exclude conversation history, previous verdicts, attempts, marked-up diffs, tailoring rationale and proposed improvements. Keep the existing editorial reviewer separate. If independent execution or a required input is unavailable, report validation as blocked and withhold the packet from ready output. A blocked check does not consume a correction.

4. **Record the verdict before acting.** For a completed inspection, save the returned JSON to a private temporary file and run `python tools/application_validation.py record "<application-key>" --after <revision> --report "<report-path>"`. Verify its file list covers the entire packet and that the inspected versions are still current before recording. On a malformed reply or stale revision, resolve the input or concurrency issue before acting; never interpret a tool error as a pass. The ledger in `documents/validation/checks.sqlite3` retains the findings and the application flag across sessions.

   - **passed:** deliver the inspected versions. Report the independent check and any factual corrections made. A subsequent edit or new document needs its own inspection of the current packet.
   - **amend:** apply only the supported corrections, preserving everything else. Fix editable sources and regenerate affected deliverables, including PDF layout checks and form counts where relevant. Go back to step 3 with the new revision. Do not send the correction list to the next validator or reopen editorial optimisation.
   - **cancelled:** the initial inspection and five correction-and-recheck cycles have found errors. Stop before another amendment or dispatch. Keep the drafts and the recorded findings. Flag **Application cancelled — validation limit reached** to the user with the company, role, affected files and unresolved discrepancies. Withhold ready status, submission and any downstream application action. This cancels the local application workflow; it is not an employer rejection or a withdrawal of an already-submitted application.
